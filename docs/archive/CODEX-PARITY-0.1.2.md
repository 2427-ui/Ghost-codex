# Ghost Studio 与原生 Codex 的工作功能对齐清单

**0.2.0 更新（2026-10-23）：下文保留 0.1.2 的规划基线。当前已接入本机协议的 168 个可操作接口，常用工作流和高级表单的覆盖见 [CODEX-INTERFACES.md](../CODEX-INTERFACES.md)，变更见 [CHANGES-0.2.0.md](../CHANGES-0.2.0.md)。下文旧版“尚未实现”不代表当前接口状态，接口入口也不代表全部官方交互已完成。**

基线：Ghost Studio 0.1.2，Windows，2026-10-23。本机已安装 Codex `0.163.0-alpha.11`。

目标是让 Ghost 的工作能力逐步覆盖原生 Codex，保留自定义眼球、桌宠和可修改人设。下表中的“后端可用”与“Studio 已实现”分开计数；同一 App Server 不会自动带来官方客户端的全部界面和服务。

## 本次完成

| 功能 | 0.1.2 行为与边界 |
| --- | --- |
| 本机历史共享 | 使用当前进程继承的同一 `CODEX_HOME`；分页读取所有来源、模型提供商、正常和归档会话。正文从 Codex 读取，保留原始 thread ID，发送时接续原会话。 |
| 本机项目导入 | 只读导入桌面端已保存的项目名称、目录、项目归属及普通聊天标记；也按历史 cwd 发现项目目录。项目的增删、排序和分组设置尚未双向同步。 |
| 普通聊天 | 初次启动无需项目即可发送；左侧“普通聊天”随时创建无项目会话。内部工作目录自动创建，不进入项目列表。默认只读；这不是禁止模型读取所有本机文件的隔离承诺。 |
| 桌宠普通聊天 | 无项目也可输入、读取历史、接续对话和汇报状态，与主窗口共用会话。 |
| 历史刷新 | 连接时、主窗口重新获得焦点时自动同步，也可手动同步；按全部、普通、当前项目和归档筛选，支持标题/来源搜索及分批显示。 |
| 历史读取 | 只读打开，不执行 resume，不修改原会话的人设与权限。真正发送时才应用当前 Studio 设置。归档历史可读，继续前需在原生客户端取消归档。 |
| 旧版升级 | 自动迁移 SQLite 的必选项目字段，保留原项目、会话引用、草稿和偏好设置。 |

共享范围是当前 App Server 可枚举、持久化到本机的 Codex 会话。ChatGPT Chat、ChatGPT Work、云端项目、远程主机及其他 `CODEX_HOME` 的记录不会仅凭同一账号自动接通。本机项目中出现某个云项目的本地目录，也不代表导入了云端聊天或上传文件。

两端已保存的内容可以接续。两端各自运行 App Server，不共享全部运行时状态和审批弹窗；不要同时在两端执行同一会话。Studio 会拒绝其后端已报告为 active 的线程，但无法保证检测到另一进程的所有活动。

## 优先补齐的功能

P1：日常编程闭环；P2：并行工作与扩展；P3：跨环境及交付完善。下表为待实施计划，本次不隐含实现。

| 优先级 | 能力 | 当前状态 | 应补齐的具体内容 |
| --- | --- | --- | --- |
| P1 | 会话管理 | 可共享、搜索标题、筛选和切换 | 重命名、归档/恢复、置顶、删除、分叉、移动到项目；正文检索另行确认协议或本地索引方案。 |
| P1 | 输入与上下文 | 文本输入、模型和推理强度选择 | 图片粘贴/拖放、附件、文件与代码选区引用、@ 文件、草稿持久化（含尚未创建的会话）、斜杠命令。 |
| P1 | 执行中交互 | 流式回复、状态、停止 | 排队跟进、执行中补充指令（steer）、任务计划面板、Plan 模式及计划确认。 |
| P1 | 工具与历史展示 | 文本、Markdown、命令、文件修改等基础展示 | 图片/附件历史、完整 MCP 工具输入输出、耗时、退出码、结构化错误、计划、子代理、富媒体与链接预览；未知记录保留可检查入口。 |
| P1 | Git 操作 | 状态、工作区/暂存 Diff | 暂存/取消暂存、提交、分支、提交历史、恢复改动、推送、创建/查看 PR。 |
| P1 | 代码审查 | Diff 与普通审查提示词 | 专用 review/start、审查范围、逐行反馈、问题定位、修改后再次审查。 |
| P1 | 集成终端 | 只显示 agent 执行的命令记录 | 独立 PTY 终端、多标签、输入/Ctrl-C、尺寸同步和退出清理。 |
| P1 | 权限与恢复 | 基础只读/项目写入、命令/文件审批、问题回答 | 细粒度目录/网络授权、会话级规则、扩展权限申请、拒绝后的继续与错误恢复。目前额外权限扩展只能拒绝。 |
| P1 | 文件工作区 | 文件树、Monaco、多标签、保存和冲突检查 | 全局文件搜索、文件监听、重命名/新建/删除、多根目录、外部编辑器打开、工作目录与原项目区分。 |
| P1 | 原生设置接续 | 同一认证与本机 Codex 环境，Studio 独立模型/权限/人设 | 显示恢复线程的实际模型和推理强度；明确每个线程配置与全局覆盖；项目分组编辑的双向同步需公开接口或版本适配。 |
| P2 | 多会话并行 | 应用同时只执行一个任务 | 按线程维护任务、审批和取消，后台任务列表、完成通知、限流和断线恢复。 |
| P2 | Worktree | 可读取已有工作目录 | 创建/关联/恢复/归档独立工作树，现有改动的处理、主目录交接和合并。 |
| P2 | Skills / MCP / 插件 | 可能继承本机已配置的部分后端能力，无完整管理界面 | 发现/启用、显式技能输入、工具可用性、MCP OAuth、配置、插件安装与兼容性；不能把后端可调用视为官方所有插件均兼容。 |
| P2 | 上下文与用量 | 模型列表、推理强度、接口有返回时显示额度 | token/context 统计、压缩提示、手动压缩、各额度窗口和重置时间、认证过期与余额不足反馈。 |
| P2 | 自动化与通知 | 桌宠状态气泡、托盘 | 系统完成/失败/审批通知、定时任务、唤醒和执行记录，项目设置脚本与快捷命令。 |
| P2 | 浏览器与预览 | 外部浏览器打开链接；Monaco 代码预览 | 内置浏览器、开发服务器预览、截图、PDF/图片/文档预览和结果附件。 |
| P3 | 远程和云任务 | 本机 Windows 执行 | WSL、SSH/远程主机、远程文件与终端、跨设备任务、云任务/托管集成。需逐项验证可用接口和账号权限。 |
| P3 | 项目与客户端完善 | 单目录项目、基础偏好和 NSIS 安装 | 多目录项目、排序/分组、完整快捷键、通知偏好、日志诊断、自动更新、代码签名、版本兼容和性能压测。 |

建议实施顺序：会话管理 → 输入/附件/引用 → 任务队列与 steer → Git/Review/终端 → 多会话与 worktree → 扩展与自动化。论文、实验与研究记忆在这些工作能力稳定后加入。

## 验收原则

不能仅凭按钮存在判定对齐。每项都应覆盖真实 App Server 行为、状态反馈、取消/失败、持久化及重启，确保权限行为与 UI 文案一致。官方客户端的私有云能力、账户插件或特定运行环境不预先承诺等价。

对齐依据：[官方 Windows 桌面功能](https://learn.chatgpt.com/docs/windows/windows-app)、[App Server 协议](https://learn.chatgpt.com/docs/app-server)、[项目与不同聊天历史的边界](https://learn.chatgpt.com/docs/projects)、[Git worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees)、[本地环境](https://learn.chatgpt.com/docs/environments/local-environment)。实际实现以本机生成的协议类型和验证结果为准。
